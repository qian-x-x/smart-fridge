# 小易冰箱 · 独立前端交互演示

直接用现代浏览器打开本目录的 **index.html**。不需要安装依赖、启动服务器、登录账号或连接后端；HTML 内含 CSS、JavaScript、SVG 食材插画和 6 张菜谱图片，可断网运行。文件约 2.65 MB。

## 可以演示什么

- **我的冰箱**：双门与双抽屉独立开合、全部关闭、场景复位、分区入口、实时统计、临期与过期提醒。
- **食材清单**：名称搜索，分类、分区、到期组合筛选，三种排序，新增、编辑、使用、移动、丢弃和过期清理。
- **今日菜谱**：6 道家常菜、图片、原料、步骤、搜索、收藏与筛选；1–6 人份调整，按库存计算主料覆盖，确认做饭后统一扣减。
- **我的家庭**：两个初始家庭、独立库存与记录、创建家庭、模拟加入、复制演示邀请码、本地成员增删与角色选择。
- **操作记录**：查看当前家庭的记录，安全撤销与恢复库存操作，导出当前家庭 JSON 数据。
- **演示设置**：只读身份、减少动画、下一次业务保存失败、本地数据导出和重置。

食材示例为 12 份，日期固定为 **2026-11-10**，方便以后重复演示。`SUNN2026` 是“晴天共享厨房”的 8 位演示邀请码，加入后体验只读成员。不会发邀请、通知或其他消息。

## 推荐演示顺序

1. 在首页打开左门、右门和抽屉，再点“全部关闭”。
2. 新增一份食材；在清单里搜索，打开详情，编辑、移动或使用。
3. 打开“番茄炒蛋”，调整人数，确认做饭；查看库存与操作记录的同步反馈。
4. 撤销做饭，观察库存恢复；再尝试恢复操作。
5. 切换到“周末小屋”，观察空冰箱；切回“林间小家”，原库存保持独立。
6. 在设置打开“模拟下一次保存失败”，尝试新增食材；首次失败保留输入，再次保存成功。
7. 体验只读身份、空搜索结果、丢弃取消与草稿关闭确认。按 `/` 聚焦食材搜索，`Esc` 关闭弹窗；有草稿时先确认。

## 实现与边界

- 单文件按样式基础、布局、厨房动画、列表、弹窗、响应式、数据、渲染、表单和动作分段组织。原生 `dialog` 提供键盘焦点约束；动态文本转义后显示。
- 仅使用独立的 `localStorage` 键 `xiaoyi-standalone-demo-v1`，不读取正式应用的会话、接口或家庭数据。浏览器禁用本地存储时，仍可在当前页面操作，并明确提示刷新后可能丢失；文件更名、移动或更换浏览器可能改变存储位置。
- 厨房由 CSS 绘制，柜内食物是装饰示意，库存以清单为准。不是正式应用的 Three.js 模型。
- 做饭只扣减列出的主料，常备调料在详情单独说明；不使用过期库存；同名同单位的多个批次按到期先后分配，缺料时禁止确认。
- 库存写入在克隆状态上校验，通过后统一更新；撤销和恢复要求当前库存与对应快照完全一致，防止覆盖后续变化。
- 检测到另一标签页更新时暂停本页写入，需刷新载入。该机制用于本地演示的旧快照保护，不等同于后端事务锁或真实多人同步。
- 只读、成员管理、收藏及邀请码均为前端演示能力，不代表正式产品已实现相应能力或安全边界。源码可由使用者修改，不提供真实身份认证。
- 菜谱图片复用本项目已生成的静白全景素材，已以 JPEG Data URL 内嵌。无需额外复制图片目录。

## 本轮验证

在仓库根目录运行：

```powershell
node scripts/review-frontend-demo.mjs
```

脚本仅使用 Node 内置模块及本机 Edge，通过 `file://` 测试，不启动应用服务器。其他安装位置可设置 `EDGE_PATH`。结果及桌面、手机截图保存在 `docs/reviews/evidence/2026-11-10-frontend-demo/`，阶段审查见 `docs/reviews/2026-11-10-frontend-demo.md`。

浏览器检查属于**本地前端演示验收**。本轮未连接正式后端，未重跑 Flutter、Java、正式应用端到端或 Android 真机验收。

项目定位：面向家庭用户的食材管理、菜谱推荐与补货应用

文档版本：V1.0（初代作品）

适用代码版本：aad85d2 之后的工作区版本，含 V1.5「暖橙食集」视觉改版

一、项目概述

本章说明项目定位、当前完成的功能范围与技术构成，便于在阅读后续章节前先明确作品边界。

（一）项目简介

小易冰箱解决的是家庭场景中三个连续问题：冰箱里有什么、这些东西什么时候过期、今天能用现有食材做什么菜。系统由 Flutter 用户端、Vue 3 运营后台和 7 个 Spring Boot 微服务组成，通过统一网关对外提供接口，数据落在 MySQL，会话与令牌状态落在 Redis。

用户端主界面是一台可交互的三维冰箱。左右门、变温室和冷冻抽屉可以独立开合，分区切换与三维场景同步；右侧库存按剩余天数排列，临期食材优先显示。菜谱页读取菜谱目录，结合当前库存计算匹配度，把「现有食材能做的菜」排在前面。

三、部署与启动

本章按基础设施、后端服务、用户端、运营后台的顺序给出启动步骤，依次执行即可复现完整演示环境。

（一）获取源码

解压提交的源码压缩包，得到 smart-fridge 目录。目录内不含依赖与构建产物，首次运行需要联网下载 Maven、npm 与 Pub 依赖。

（二）启动基础设施

在项目根目录执行：

.\scripts\Start-Core.ps1

脚本首次运行会从 .env.example 生成本地配置 infra/compose/.env，随后启动 Nacos、核心 MySQL、交易 MySQL、Redis 与 MinIO，并输出容器状态。

等待约 30 秒，确认容器均为运行状态：

docker compose --env-file infra/compose/.env -f infra/compose/compose.core.yml ps

数据库无需手工建表。三个业务服务启动时由 Flyway 自动执行 db/migration 下的脚本，创建账号、家庭、冰箱、食材、操作流水与菜谱等表结构，并写入菜谱种子数据。

（三）启动后端服务

先安装父工程与公共模块，再按依赖顺序启动服务。每个服务使用独立终端窗口。

cd backend

mvn -DskipTests install

启动顺序命令说明
1mvn -pl auth-family-service spring-boot:run账号与家庭服务，冰箱服务启动时依赖它
2mvn -pl fridge-service spring-boot:run冰箱与食材服务
3mvn -pl recipe-service spring-boot:run菜谱目录服务
4mvn -pl gateway-service spring-boot:run网关，最后启动以便路由到已就绪的服务

默认使用 local 配置：关闭 Nacos 注册，服务直接监听本机端口，网关按固定地址转发到 8081 至 8086。若需要演示服务发现，把 SPRING_PROFILES_ACTIVE 设为 cloud、NACOS_ENABLED 设为 true 后重启对应服务。

健康检查可用任意一个服务的探针接口验证：

curl http://127.0.0.1:8081/actuator/health

curl http://127.0.0.1:8080/actuator/health

（四）启动用户端

浏览器方式：

cd apps/fridge-app

flutter run -d chrome --dart-define=API_BASE_URL=http://localhost:8080

Android 模拟器需要把宿主机地址映射为 10.0.2.2：

flutter run -d emulator-5554 --dart-define=API_BASE_URL=http://10.0.2.2:8080

首次运行会下载 Pub 依赖并编译，耗时较长。编译完成后浏览器自动打开登录页。

若只需要查看界面、暂时不启动后端，可在登录页点击「先用演示数据看看」进入演示模式，说明见第 5 章。

（五）启动运营后台

cd apps/admin-web

npm install

npm run dev

浏览器访问 http://localhost:5173，在登录页选择「直接浏览演示」进入。

（六）启动结果检查

按下列顺序逐项确认，任一环节失败先处理再继续：

  1. docker ps 中 MySQL、Redis、Nacos、MinIO 均为 Up。
  2. 8081、8082、8083 三个服务的启动日志出现 Started ... in ... seconds。
  3. 访问 http://127.0.0.1:8080/api/v1/recipes 返回统一响应结构，code 为成功码。
  4. 用户端停留在登录页且无红色错误提示。
  5. 运营后台可进入看板页。

四、功能使用说明

本章按用户实际操作顺序说明各功能的入口与交互方式，配图均为本地真实运行截图。

（一）注册与登录

首次使用点击登录页底部「创建账号」，填写用户名、手机号与密码。密码由后端 BCrypt 加密后存储，接口不回传明文。注册成功后自动进入首页。

登录成功后，访问令牌有效期 30 分钟，刷新令牌有效期 7 天且一次性使用。令牌过期时客户端自动刷新并重放原请求；刷新失败则回到登录页。点击「退出当前账号」会把当前访问令牌写入撤销名单，即使令牌未到期也不能继续使用。

（二）首页与三维冰箱

首页自上而下分为三层：顶部品牌栏与家庭名、中部食材提示条与分区切换、下部三维场景与库存概览。

三维场景支持以下操作：

操作效果
拖动画面改变观察角度，模型不会拖出视口
点击「左门」「右门」对应门绕外侧铰链打开，两门共用冷藏内腔
点击「变温」「冷冻」抽屉沿轨道前移，其余门与抽屉保持原状态
点击「全部关闭」所有门与抽屉复位
点击「展开概览」回到默认观察角度

分区按钮（冷藏、变温、冷冻、常温）与三维场景联动：切换分区时场景高亮对应区域，库存列表同步过滤。常温区位于厨房侧台面，不在冰箱主体内。

模型中的食材几何体按当前库存生成，每个分区最多渲染 12 个几何体，完整清单仍保留在右侧列表。这样既保证渲染性能，也不会因为图形数量限制而隐藏数据。

（三）食材管理

点击右上角「放进一份新食材」打开录入表单，填写名称、分类、数量、单位、分区与到期日期。分类使用预设选项，选择后与三维场景的分区保持一致。

保存成功后，库存列表、分区计数与三维场景同时更新，后端追加一条 ADD 操作流水。食材卡片支持以下操作：

操作说明
编辑修改名称、数量、到期日期等字段
移动在四个分区之间转移，生成 MOVE 流水
消耗记录本次用量，数量减至零时标记为已用完
丢弃标记为丢弃，保留历史记录

所有写操作携带版本号。若两人同时修改同一条食材，后提交的一方会收到 409 冲突，客户端提示刷新后重试，不会出现后写覆盖先写。

点击库存列表中的食材可查看详情，包括剩余天数、数量、记录人与当前账号权限。

（四）筛选与排序

点击「食材清单」或「全部食材与筛选」打开筛选面板，支持以下条件组合：

  • 名称关键字搜索；
  • 分类多选；
  • 标签多选；
  • 分区筛选；
  • 到期状态（全部、临期、已过期）；
  • 到期日期区间。

排序支持按到期时间、入库时间、名称与数量四种方式。筛选结果只影响清单，不改变三维场景中的完整库存，避免用户误以为食材被删除。

（五）菜谱推荐

菜谱页从菜谱服务读取目录，结合当前家庭库存计算匹配度。匹配规则为：菜谱原料名称与库存食材名称或别名一致即视为已有，番茄与西红柿、土豆与马铃薯等常见别名已内置。

推荐结果按「覆盖率、临期食材命中数、是否精选、烹饪时长」依次排序。每张卡片显示匹配百分比、已具备的原料数量、缺少的原料以及预计耗时。切换到「临期优先」可只查看能用掉临期食材的菜谱。

原料匹配在客户端完成，不额外发起跨服务调用，因此切换筛选条件时列表即时刷新。

（六）家庭协作

家庭是数据隔离的边界：一台冰箱只属于一个家庭，食材、操作流水与菜谱匹配都按家庭隔离。成员角色分为所有者、编辑者与查看者。

操作入口说明
创建家庭家庭与设置页「创建家庭」创建者成为所有者
加入家庭「加入家庭」输入 8 位邀请码邀请码去掉了易混淆的 I、L、O、0、1
调整角色成员管理中选择成员所有者可把成员设为编辑者或查看者
转交所有权成员管理中选择接收人原所有者降为编辑者，接收人升为所有者
切换家庭顶部家庭名下拉切换后冰箱与菜谱按新家庭重新加载

查看者可以浏览全部数据，但不能新增、修改或删除食材。该限制在服务端校验：冰箱服务在处理写操作时回查认证服务的家庭角色，前端按钮状态不作为授权依据。因此即使绕过界面直接调用接口，查看者仍会被拒绝。

（七）运营后台

运营后台面向运营人员，包含数据看板、菜谱管理、商品库存与订单四个页面。看板使用 ECharts 展示食材分类分布与临期趋势。

当前版本运营后台使用演示数据，页面顶部有明确标注。真实运营接口尚未落地，因此后台的增删改不会影响用户端数据。这一限制在第 8 章中一并说明。

（八）手机端

用户端为响应式布局。宽度小于 600 逻辑像素时，左侧导航收起为底部标签栏，库存概览移到页面下方，三维场景保持可拖动与可点击。分区按钮与底部操作条在小屏下自动换行，不出现横向滚动。

五、演示模式与数据说明

登录页提供「先用演示数据看看」入口。演示模式在本地构造一份家庭与库存数据，不访问后端，用于在没有启动服务时检查界面与交互。

演示模式有三个明确限制：

  1. 数据只存在于内存，刷新页面即恢复初始状态；
  2. 写操作不会持久化，也不会产生操作流水；
  3. 顶部显示「演示模式 · 仅供浏览」，避免与真实数据混淆。

需要验证真实链路时，请按第 3 章启动后端并注册账号。演示模式不能作为功能验收依据。

七、常见问题

现象原因处理方式
8848、3306 或 3307 端口被占用本机已有同类服务停止冲突进程，或修改 compose.core.yml 的端口映射
Nacos 中看不到服务未启用注册设置 SPRING_PROFILES_ACTIVE=cloud 与 NACOS_ENABLED=true 后重启服务
网关返回 503目标服务未就绪或未注册确认服务已启动，local 配置下检查端口是否为 8081 至 8083
网关返回 401请求缺少或携带过期令牌重新登录，或在请求头加入 Authorization: Bearer <accessToken>
登出后接口仍可访问Redis 未运行，撤销名单未写入启动 Redis，确认 auth:revoked:{jti} 键存在
三维场景空白浏览器关闭了硬件加速在浏览器设置中开启硬件加速，或改用支持 WebGL 2 的浏览器
三维场景显示降级提示WebGL 不可用此时食材清单仍可正常使用，属预期降级
保存食材返回 409数据已被他人修改刷新页面获取最新版本后重新提交
flutter analyze 报路径异常项目位于中文路径改用 dart analyze lib test，或在纯英文路径下构建
加入家庭提示邀请码无效邀请码区分大小写且为 8 位核对邀请码，确认未包含被剔除的字符

八、已知限制

为避免误解，以下能力在本版本中尚未完成，界面与文档均已如实标注。

  1. 时间线撤销与恢复：操作流水已按 ADD、MOVE、CONSUME、UPDATE、DISCARD 记录，并预留了原始操作关联字段，但撤销接口与时间线页面尚未实现。
  2. 实时同步：家庭成员之间的数据变更需要手动刷新，WebSocket 推送尚未接入。
  3. 做饭扣减：菜谱页可以查看做法，但不会按菜谱用量扣减库存，也没有烹饪记录。
  4. 补货交易：商品库存、补货单、优惠券与支付仅有服务骨架，未接入真实业务。
  5. 运营后台数据：页面使用演示数据，尚未对接真实运营接口。
  6. 中间件治理：Seata、Sentinel、RocketMQ 与 SkyWalking 仅有容器编排与依赖配置，没有真实业务调用证据。
  7. 移动端签名：Android 安装包使用调试签名，仅用于本地验收，未进行真机分发验收。
  8. 素材与内容：正式商品图、菜谱配图与完整菜谱库尚未补齐，当前使用内置种子数据与示意图。

上述项目不影响已完成功能的演示与验收，但不应在答辩中描述为已实现。

附录 B 主要接口

所有接口经网关 8080 转发，除注册与登录外均需携带访问令牌。响应统一为 code、message、data、traceId 四个字段。

方法路径说明
POST/api/v1/auth/register注册账号
POST/api/v1/auth/login登录并签发令牌
POST/api/v1/auth/refresh刷新访问令牌
POST/api/v1/auth/logout登出并撤销令牌
GET/api/v1/families查询当前账号的家庭
POST/api/v1/families创建家庭
POST/api/v1/families/join使用邀请码加入家庭
GET/api/v1/families/{familyId}查询家庭详情与当前账号角色
GET/api/v1/families/{familyId}/members查询家庭成员
POST/api/v1/families/{familyId}/transfer-owner转交所有权
GET/api/v1/fridges?familyId={familyId}查询家庭冰箱结构
POST/api/v1/fridges创建冰箱
GET/api/v1/foods按条件查询食材
POST/api/v1/foods新增食材
PUT/api/v1/foods/{foodId}修改食材（需携带版本号）
POST/api/v1/foods/{foodId}/move移动食材到其他分区
POST/api/v1/foods/{foodId}/consume消耗食材
DELETE/api/v1/foods/{foodId}丢弃食材（软删除并记录流水）
GET/api/v1/recipes查询菜谱目录
GET/api/v1/recipes/{recipeId}查询菜谱详情

接口字段与错误码的完整定义见 contracts/openapi/smart-fridge-v1.yaml。

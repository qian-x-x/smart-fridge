# 小满冰箱 · 三套前端 UI 设计提案

日期：2026-10-31。最新状态：用户已选择 C「暖橙食集」并授权实现，品牌更名为「小易冰箱」，口号「查食材，看菜谱，都容易」。实现及验证见 [阶段审查](../../reviews/2026-10-31-warm-harvest-xiaoyi.md)和[实际截图](../warm-harvest/验收记录.md)。

以下及原型、90 张 PNG 保留当时选稿名称与模拟数据，作为历史设计提案。下文「本轮只制作设计稿」指选稿阶段，不代表当前尚未实现。

## 页面切换设计

| 行为 | A 晨光厨房 | B 冰川秩序 | C 暖橙食集 |
| --- | --- | --- | --- |
| 同级页面切换 | 260ms 淡入 + 10px 上移 | 200ms 淡入 + 16px 横移 | 310ms 淡入 + 14px 上移 + 轻微缩放 |
| 导航选中反馈 | 浅绿底 + 图标与文字加深 | 蓝色选中块 + 顶部导航定位 | 暖色底块 + 窄轨突出当前项 |
| 详情 / 表单 | 桌面居中浮层，手机底部弹层 | 更紧凑的内容与字段组织 | 更柔和的圆角与分组 |
| 减少动态效果 | 直接切换，不播放位移或缩放 | 同左 | 同左 |

实现时应保留同一页面的筛选、滚动位置和家庭上下文，返回后恢复；切换家庭先撤下旧家庭数据，再展示新家庭快照。家庭、库存与菜谱状态不能在过渡中串用。表单关闭如有未保存内容，应明确提示，避免误丢输入。上述业务状态恢复要求需在选定方案后针对生产代码实现、审查和回归，本轮不会以原型替代。

弹层须置于全局导航之上，遮罩期间暂停三维输入；移动端操作区避开底部导航、系统安全区和软键盘。真实三维开门、抽屉拉出及拖拽应保持独立于普通页面动效，避免每次切页都重建场景。

## 按钮与反馈设计

- 悬停：轻微亮度、阴影变化，保持文字位置稳定。关键操作始终可见，不依赖悬停出现。
- 按下：120ms 轻微压缩到约 97%，抬手复原；主按钮保留明确实色。
- 提交中：立即锁定当前提交按钮，文字改为“正在保存…”，防止重复操作。
- 成功：主按钮短暂显示完成勾选并出现轻提示；等待真实请求成功后才更新生产数据。
- 失败：错误放在当前上下文内，保留输入并提供重试；不反复弹出全屏错误。
- 数据冲突：提示家人已更新，先刷新再确认，不自动重放写请求。
- 权限不足：写入口禁用并说明“只读权限”；重要状态不能只靠透明度表达。
- 丢弃、移除、转交和退出：二次确认显示对象和具体影响；尚无撤销功能的操作不展示“可撤销”承诺。

## 原型能力与边界

可实际体验：页面选择、方案切换、主要导航、食材详情、菜谱详情、搜索示例、菜谱条件、数量上下限、密码可见性、表单提交锁定和成功反馈、确认取消、页面切换与减少动态效果。

原型完全本地运行，不请求业务 API，不提交账号、库存、家庭或订单数据。“复制”只展示视觉反馈，不改剪贴板。食材筛选交互仅演示名称匹配；其他组合字段展示设计布局，不代表完整筛选实现。家庭切换、成员角色调整、移动和使用等显示演示反馈，不代表后端业务完成。原型切页后的业务状态持久化不作为本轮验收项。

推送、布局编辑、其他主题正式切换、做饭确认、自动扣减、时间线撤销 / 恢复、商品编辑、订单详情和导出不因本稿而变为已实现能力；相关入口保持说明或演示标记。

三套厨房和菜谱摄影素材通过内置 imagegen 生成，提示词与用途见 [image-prompts.json](image-prompts.json)。厨房为概念视觉，不是现有实时 Three.js 模型渲染结果；食材摆放数量不作为库存事实。后续若选择该方向，需要分别处理场景模型、材质、图片与运行性能的落地。

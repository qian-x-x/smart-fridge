## 3. 运行后端

默认 profile 是 **cloud**：日常运行 gateway/auth/fridge/recipe 四个业务服务，在 Nacos 的 `SMART_FRIDGE` 分组注册，网关走 `lb://`。本轮家庭初始化还依赖 Seata，启动前必须启动其 RPC 服务。首次准备 Seata、SkyWalking 及 agent 的命令见 5.1.3、5.1.4；已存在的本地容器可用 `docker start smart-fridge-seata smart-fridge-skywalking-oap smart-fridge-skywalking-ui` 恢复。

`.\scripts\Start-Services.ps1` 默认启动四个真实业务服务，给每个 JVM 设置 256 MB 最大堆并逐个等待健康，避免同时加载 agent 耗尽 Docker 内存。历史 order/stock 需要额外启动 MySQL trade 并显式传入 `-IncludeLegacyDemo`。

没有注册中心时可用降级模式：`$env:SPRING_PROFILES_ACTIVE='local'`，网关改用 `application-local.yml` 的固定地址（8081–8085）。降级模式只影响路由，不影响其他服务注册。

若同时关闭 auth/fridge 的 Nacos（`NACOS_ENABLED=false`），还需在宿主机进程中显式设置 `FRIDGE_SERVICE_URL=http://127.0.0.1:8082` 和 `AUTH_SERVICE_URL=http://127.0.0.1:8081`。默认留空时两个 Feign 客户端按 Nacos 名称发现，local 网关路由不会替代服务间发现；真实家庭初始化仍需 Seata。

Gateway 会调用认证 introspect 校验撤销状态，认证服务故障时返回 503，客户端应保留会话并重试。

```powershell
cd backend
mvn -DskipTests install
mvn -pl auth-family-service spring-boot:run
```

认证家庭服务地址为 `http://localhost:8081`。

需要验证服务发现和 Gateway 路由时，使用 cloud profile：

```powershell
$env:SPRING_PROFILES_ACTIVE = "cloud"
$env:NACOS_ENABLED = "true"
mvn -pl auth-family-service spring-boot:run
```

在另一个 PowerShell 窗口：

```powershell
$env:SPRING_PROFILES_ACTIVE = "cloud"
$env:NACOS_ENABLED = "true"
mvn -pl gateway-service spring-boot:run
```

环境变量只对当前 PowerShell 会话生效。生产或共享环境必须覆盖 `JWT_SECRET`、MySQL 密码和 Redis 密码。

## 5.1 容器化运行服务（端到端验收用）

基础设施用 core Compose 起好后，可把可执行 jar 放进 `eclipse-temurin:17-jre` 容器，与 MySQL/Redis 同网络运行，避免宿主机端口与进程干扰：

| 服务 | 关键环境变量 |
| --- | --- |
| auth-family | `MYSQL_CORE_URL`（主机名 `mysql-core`）、`REDIS_HOST=redis`、`REDIS_PASSWORD`、`SEATA_ADDR=smart-fridge-seata:8091` |
| fridge | 同上 MySQL、Seata；`AUTH_SERVICE_URL` 默认留空，Feign 按 Nacos 服务名发现 auth |
| recipe | `MYSQL_CORE_URL` 指向 `recipe_db` |
| gateway | **`AUTH_SERVICE_URL`（必填，否则令牌校验 503）**；默认走 `lb://` 时只需 `NACOS_ADDR` |
| stock/order（历史验证） | `MYSQL_TRADE_URL`、交易库账号密码、`NACOS_ADDR`、`SEATA_ADDR` |

网关默认把 `smart-fridge.auth-service-url` 指向 `http://127.0.0.1:8081`，在容器内这是它自己，必须显式覆盖，否则所有带令牌请求返回 503「认证服务暂时不可用」。

容器内的 MySQL 主机名用 `mysql-core` 而不是 `127.0.0.1`；连接串里的 `&` 需用引号包裹整个参数。

端到端验收脚本：

## 5.1.0 真实家庭初始化验收（2026-11-09）

用户端“创建家庭”调用 `POST /api/v1/families/workspaces`，提交 `name` 和 `requestId`。auth 写家庭与 OWNER 成员，通过 Feign 按 `fridge-service` 服务名初始化冰箱、冷藏/变温/冷冻三区及五个容器。Seata AT 同时管理 `auth_db`、`fridge_db` 的分支事务。Flyway 在建立 Seata 代理前迁移原始数据源。

升级到 Flyway V5 前等待正在处理的家庭初始化和食材写入完成，再用新版本替换旧 `fridge-service`。V5 把原常温食材和相关流水位置归入各自冰箱的冷藏区，保留食材数量、日期和状态，清除对旧储物筐的引用。

首次提交返回 201，已提交的同用户同请求重放返回 200。不同用户的请求标识相互隔离；同标识不同名称或仍在处理返回 409。Sentinel 入口限流返回 429，初始化依赖不可用或熔断返回 503。Flutter 在当前会话内保留失败请求标识供重试；成功后直接使用返回家庭，后续列表或本地存储失败不再把已提交创建显示为失败。重启应用会重新读取服务端家庭列表。

Gateway 清除客户端 `TX_XID` 和伪造身份头；服务间传播后端创建的 XID。公开创建入口拒绝外部事务上下文。全局决定前的家庭对普通读取、加入及管理请求不可用；权限回调只允许相同 XID 访问。可见性检查使用独立的 READ_COMMITTED 读取，避免复用回滚前的旧快照。

隔离验收使用 `auth_business` / `fridge_business` / `recipe_business`、独立 Nacos 分组、专用 JWT 密钥和 18080 等端口。以下脚本会创建验收数据；不清空原开发库：

```powershell
.\scripts\Start-BusinessAcceptance.ps1 -Scope Core
.\scripts\Start-BusinessAcceptance.ps1 -SkipBuild -Scope Fault
$env:OUT_DIR = 'docs/reviews/evidence/2026-11-09-real-business'
python scripts/verify-family-workspace.py
python scripts/query-family-workspace-traces.py
```

故障代理仅运行在隔离验收环境，模拟依赖拒绝、下游写入后响应丢失及超时；产品 API 没有增加故障注入参数。验收完成后停止 `sf-business-auth-fault` / `sf-business-proxy` 再启动 `-Scope Recipe`，避免额外 JVM 叠加。Web 验收由 `ui-acceptance-family-workspace.mjs` 驱动 release 产物，默认入口 `http://127.0.0.1:18000`，需 nginx 同源代理到隔离网关；登录上下文只保存在被忽略的 `output/real-business/`。

本轮命令、证据和未完成验收见 [真实家庭业务审查](reviews/2026-11-09-real-family-workspace.md)。下文 N2–N4 的订单链路属于历史技术验证。

## 5.1.1 Nacos 外置配置与动态刷新

`fridge-service` 的临期阈值来自 Nacos，DataId 为 `fridge-service.yaml`、分组 `SMART_FRIDGE`，对应 `application-cloud.yml` 里的：

```
spring.config.import: optional:nacos:${spring.application.name}.yaml?group=SMART_FRIDGE&refreshEnabled=true
```

发布配置（**必须用单行 flow-style YAML**，见下方注意事项）：

```
curl -X POST "http://127.0.0.1:8848/nacos/v1/cs/configs" ^
  --data-urlencode "dataId=fridge-service.yaml" ^
  --data-urlencode "group=SMART_FRIDGE" ^
  --data-urlencode "type=yaml" ^
  --data-urlencode "content={\"smart-fridge\": {\"fridge\": {\"expiring-threshold-days\": 10}}}"
```

验证刷新：同一份 5 天后到期的食材，阈值设为 1 时 `expiring=false`，改为 10 后变成 `true`，服务无需重启。完整断言见 `scripts/Smoke-Nacos.ps1`，13 项。

> **注意事项**：用表单提交**多行** YAML 时，Nacos 2.4.3 会把换行存成字面 `/n`（读回是 `a:/n  b: 1`），配置解析失败但接口不报错，表现为“改了配置却不生效”。统一使用单行 flow-style YAML 可以规避。排查时先 `GET /nacos/v1/cs/configs?dataId=...&group=...` 确认内容是否完整。

## 5.1.2 超时、流控与熔断

`order-service` 通过服务名调用 `stock-service`，保护分两层：

| 机制 | 资源 | 参数 | 触发结果 |
| --- | --- | --- | --- |
| Feign 超时 | `StockClient` | 连接 1000ms、读取 1500ms | 503 `库存服务调用失败：响应超时（超过 1500ms 未返回）` |
| 流控 QPS | `order-create` | 2 次/秒，快速失败 | 429 `下单请求过于频繁（QPS 上限 2）` |
| 熔断（慢调用比例） | `stock-deduct` | 慢呼 >500ms、比例 >0.5、最小 2 次、窗口 10s、熔断 10s | 503 `库存服务已熔断，本次未发起调用`（不请求下游） |

规则由 `SentinelRules` 在启动时装载，阈值可用环境变量覆盖：`ORDER_QPS`、`SLOW_CALL_MILLIS`、`SLOW_RATIO`、`FEIGN_READ_TIMEOUT_MS`。

手工制造三种场景（`stockDelayMs` 只用于演示，正常下单不传）：

```
# 超时：延迟 3000ms > 读超时 1500ms
curl -X POST http://127.0.0.1:8085/api/v1/orders -H "Content-Type: application/json" ^
  -d "{\"sku\":\"APPLE\",\"quantity\":1,\"stockDelayMs\":3000}"

# 熔断：连续 2 次延迟 800ms（慢但成功），第 3 次直接返回熔断
curl -X POST http://127.0.0.1:8085/api/v1/orders -H "Content-Type: application/json" ^
  -d "{\"sku\":\"APPLE\",\"quantity\":1,\"stockDelayMs\":800}"

# 流控：并发 6 个无延迟请求
```

熔断/流控的触发记录看 order 容器日志里的 `blocked by circuit breaker` / `rate limited`，日志会连带打印规则对象。可选启动控制台：`docker compose -f infra/compose/compose.full.yml up -d sentinel-dashboard`，访问 `http://localhost:8858`（sentinel/sentinel）。

## 5.1.3 Seata 跨服务事务

库存与订单分属两个库，一次下单是跨库事务：

| 角色 | 服务 | 数据源 | 一阶段 |
| --- | --- | --- | --- |
| TM | `order-service` | `order_db` | 写 `order_record`（PENDING） |
| RM | `stock-service` | `stock_db` | `UPDATE stock_item SET stock = stock - ?` |

协调者 `seata-server` 2.1.0 用 file 存储，端口 8091（RPC）与 7091（控制台）：

```powershell
docker run -d --name smart-fridge-seata --network smart-fridge `
  -p 8091:8091 -p 7091:7091 `
  -e SEATA_PORT=8091 -e STORE_MODE=file -e SERVER_NODE=1 `
  -v seata-data:/root/seata-server apache/seata-server:2.1.0
```

两个服务的环境变量：

| 变量 | 值 | 说明 |
| --- | --- | --- |
| `MYSQL_TRADE_URL` | `jdbc:mysql://mysql-trade:3306/stock_db?...` / `...order_db?...` | 各连各的库 |
| `MYSQL_TRADE_USER` / `MYSQL_TRADE_PASSWORD` | `smart_fridge_trade` / `smart_fridge_trade_dev` | |
| `SEATA_ADDR` | `smart-fridge-seata:8091` | 客户端的 grouplist 地址 |

建表脚本在 `infra/mysql/trade/002_trade_tables.sql`，已有数据卷时手工执行一次：

```powershell
docker exec -i smart-fridge-mysql-trade mysql -usmart_fridge_trade -psmart_fridge_trade_dev `
  < infra/mysql/trade/002_trade_tables.sql
```

演示三种结果（`failAfterDeduct` 只用于演示，正常下单不传）：

```powershell
# 成功：库存扣减、订单 CREATED、二阶段提交
curl -X POST http://127.0.0.1:8085/api/v1/orders -H "Content-Type: application/json" -d '{\"sku\":\"APPLE\",\"quantity\":2}'

# 库存不足：抛异常触发全局回滚，订单不落库
curl -X POST http://127.0.0.1:8085/api/v1/orders -H "Content-Type: application/json" -d '{\"sku\":\"EGG\",\"quantity\":9999}'

# 人为失败：库存已扣减后失败，库存被 undo_log 还原
curl -X POST http://127.0.0.1:8085/api/v1/orders -H "Content-Type: application/json" -d '{\"sku\":\"APPLE\",\"quantity\":3,\"failAfterDeduct\":true}'
```

核对回滚：

```powershell
docker exec smart-fridge-mysql-trade mysql -usmart_fridge_trade -psmart_fridge_trade_dev -e `
  "SELECT sku, stock FROM stock_db.stock_item; SELECT order_id, status FROM order_db.order_record; SELECT COUNT(*) FROM stock_db.undo_log; SELECT COUNT(*) FROM order_db.undo_log;"
```

日志关键字：stock 侧 `branch rollback success`、`undo_log deleted with GlobalFinished`；seata 侧 `Rollback global transaction successfully`。

> 注意：`stock` 与 `order` 的 `undo_log` 必须各自存在，缺了回滚时会报 `undo_log table not exist`。建表脚本里的 `SET NAMES utf8mb4` 也不能删，否则商品名会被双重编码。

## 5.1.4 SkyWalking 链路追踪

| 组件 | 端口 | 说明 |
| --- | --- | --- |
| OAP `apache/skywalking-oap-server:10.1.0` | 11800（gRPC 上报）、12800（GraphQL） | H2 存储 |
| UI `apache/skywalking-ui:10.1.0` | 8088 | 服务列表、拓扑、链路 |

```powershell
docker run -d --name smart-fridge-skywalking-oap --network smart-fridge --network-alias skywalking-oap `
  -p 11800:11800 -p 12800:12800 -e TZ=Asia/Shanghai -e SW_STORAGE=h2 -e JAVA_OPTS="-Xms256m -Xmx512m" `
  -v skywalking-data:/skywalking/data apache/skywalking-oap-server:10.1.0

docker run -d --name smart-fridge-skywalking-ui --network smart-fridge --network-alias skywalking-ui `
  -p 8088:8080 -e TZ=Asia/Shanghai -e SW_OAP_ADDRESS=http://skywalking-oap:12800 apache/skywalking-ui:10.1.0
```

agent 从镜像导出一次即可（39MB，已在 `.gitignore`）：

```powershell
docker rm -f sw-agent-tmp 2>$null
docker create --name sw-agent-tmp apache/skywalking-java-agent:9.6.0-java17
docker cp sw-agent-tmp:/skywalking/agent infra/skywalking/agent
docker rm -f sw-agent-tmp
# 网关插件默认在 optional-plugins 里，必须拷到 plugins 才生效
Copy-Item infra\skywalking\agent\optional-plugins\apm-spring-cloud-gateway-4.x-plugin-9.6.0.jar infra\skywalking\agent\plugins\
Copy-Item infra\skywalking\agent\optional-plugins\apm-spring-webflux-6.x-plugin-9.6.0.jar infra\skywalking\agent\plugins\
```

`scripts/Start-Services.ps1` 会自动挂 agent（服务名、backend_service、`SW_LOGGING_DIR` 都注入好）。不加 agent 时用 `-WithoutAgent`。

两个必须踩对的点：

- **OAP 时区**：容器默认 UTC，GraphQL 的 `queryDuration` 按 OAP 本地时间解析。少了 `TZ=Asia/Shanghai` 会表现为"UI 和接口都查不到 trace"，而 agent 其实正常上报。
- **网关插件**：不拷 `apm-spring-cloud-gateway-4.x-plugin`，网关只有自己发出去的 WebClient span，没有 `POST /api/v1/orders` 的入口 span，拓扑图缺"用户 → 网关"这一段。

验收与取证：


## 5.2 Web 与局域网访问

Web 由 nginx 容器托管，并把 `/api/` 同源反代到网关，因此浏览器不会跨源请求 8080。容器发布在 `127.0.0.1:3030`，对外统一用 `3000`：

```
docker rm -f sf-web
docker run -d --name sf-web --network smart-fridge -p 3030:80 ^
  -v "<repo>/infra/web/nginx.conf:/etc/nginx/conf.d/default.conf:ro" ^
  -v "<repo>/apps/fridge-app/build/web:/usr/share/nginx/html:ro" nginx:alpine
```

Docker Desktop for Windows 只把 `-p` 端口发布到回环地址，局域网设备需要额外一层转发，二选一：

| 方式 | 命令 | 说明 |
| --- | --- | --- |
| 系统端口代理（推荐） | `scripts/Enable-LanAccess.ps1` | 需管理员；`netsh interface portproxy` + 防火墙放行，重启后仍有效；加 `-Remove` 撤销 |
| 用户态转发（免提权） | `python scripts/lan-bridge.py 3000=3030` | 普通权限即可，进程退出后失效 |
| 宿主机静态服务（免提权） | 见下方命令 | Docker 端口只发布到回环时的替代方案，`/api` 直连回环网关 |

宿主机静态服务用于 `netsh` 无法使用（无管理员权限）的场景。它直接托管 `apps/fridge-app/build/web`，并把 `/api/` 转发到回环网关，因此 nginx 容器可以不参与：

```powershell
$env:PREVIEW_HOST='0.0.0.0'; $env:PREVIEW_PORT='3000'; $env:PREVIEW_API='http://127.0.0.1:8080'
node scripts/preview-quiet-white.mjs
```

`PREVIEW_HOST` 默认 `127.0.0.1`（隔离预览 18000）；改成 `0.0.0.0` 后同一 Wi-Fi 的手机可访问 `http://<电脑局域网IP>:3000`。该进程随终端退出而结束，长期运行仍建议管理员执行 portproxy。判断是否必须走这条路：`Get-NetTCPConnection -LocalPort 3030 -State Listen` 若只有回环地址，说明容器端口没有对外发布。

之后在手机浏览器打开 `http://<电脑局域网IP>:3000`。查询本机地址：`Get-NetIPAddress -AddressFamily IPv4`，排除 `127.*` 与 `169.254.*` 后取 WLAN 那一项。

独立预览也可以复用此脚本。将 `PREVIEW_BUILD_DIR` 指向 Flutter `--output` 的构建目录，`PREVIEW_API` 指向目标网关，例如 `http://127.0.0.1:8080`。本机访问使用 `PREVIEW_HOST=127.0.0.1`。同一 Wi-Fi 的设备访问时，将 `PREVIEW_HOST` 设为电脑当前的 WLAN IPv4 地址，并使用 `PREVIEW_PORT` 指定的端口。如果预览由 `python -m http.server` 托管，登录 POST 会返回 501。

注意事项：

- 手机与电脑需在同一 Wi-Fi；Windows 防火墙若为「公用网络」，需允许该端口入站（脚本会自动加规则）。
- 页面是 `http`，Web 端会话存在 `localStorage`（`flutter_secure_storage` 依赖 WebCrypto，在非安全上下文会静默失败）。要回到系统级安全存储，请给站点配 https。
- Web 版用页面源作为 API 地址；原生 Android 需 `--dart-define=API_BASE_URL=http://<IP>:8080`。

## 8. 常见问题

- `8848`、`3306` 或 `3307` 被占用：先检查本机是否已有 Nacos/MySQL，再调整 Compose 端口或停止冲突进程。
- Nacos 中看不到服务：确认未设置 `SPRING_PROFILES_ACTIVE=local`（降级模式不注册）、`NACOS_ADDR` 指向可达地址，并检查容器健康状态。
- 改了 Nacos 配置但接口没变化：先确认配置内容完整（多行 YAML 会被存成 `/n`），再看 fridge 日志是否出现 `Receive Nacos config change` 与 `Refresh keys changed`。
- Gateway 返回 503：确认目标服务已注册到 Nacos，服务名与路由 `lb://` 地址一致。
- Gateway 返回 401：登录接口以外的请求必须携带 `Authorization: Bearer <accessToken>`。
- 登出后访问家庭接口仍成功：确认 Redis 正常运行，访问令牌的 `jti` 应写入 `auth:revoked:{jti}`。

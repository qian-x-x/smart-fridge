# 开发运行手册

## 1. 环境检查

```powershell
java -version
mvn --version
flutter --version
node --version
docker version
docker compose version
```

基线版本：

- JDK 17
- Maven 3.9
- Flutter 3.47.8 / Dart 3.13.7
- Node.js 22
- Docker Desktop，支持 Compose v2 或更高版本

## 2. 基础设施

轻量开发环境：

```powershell

```

启动 Nacos、MySQL core、MySQL trade、Redis 和 MinIO。首次运行会从 `.env.example` 生成被 Git 忽略的 `infra/compose/.env`。

```powershell
.\scripts\Start-Full.ps1
```

额外启动 RocketMQ、Seata、Sentinel 和 SkyWalking。16 GB 内存机器建议先启动 core，演示治理组件时分批启动，并在 `docker stats` 中确认内存压力。

## 3. 运行后端

默认 local 模式关闭 Nacos，可直接连接 Docker 中的 MySQL 与 Redis。

Gateway 的 local profile 使用 `application-local.yml` 直连本机 8081–8086；不需要手工覆盖路由数组。cloud profile 继续采用 Nacos 服务发现。Gateway 会调用认证 introspect 校验撤销状态，认证服务故障时返回 503，客户端应保留会话并重试。

```powershell
cd backend
mvn -DskipTests install
mvn -pl auth-family-service spring-boot:run
```

认证家庭服务地址为 `http://localhost:8081`。

需要验证服务发现和 Gateway 路由时，使用 cloud profile：

```powershell
$env:SPRING_PROFILES_ACTIVE = "cloud"
$env:NACOS_ENABLED = "true"
mvn -pl auth-family-service spring-boot:run
```

在另一个 PowerShell 窗口：

```powershell
$env:SPRING_PROFILES_ACTIVE = "cloud"
$env:NACOS_ENABLED = "true"
mvn -pl gateway-service spring-boot:run
```

环境变量只对当前 PowerShell 会话生效。生产或共享环境必须覆盖 `JWT_SECRET`、MySQL 密码、Redis 密码和 MinIO 密码。

## 4. 运行 Flutter

Web：

```powershell
cd apps/fridge-app
flutter run -d chrome --dart-define=API_BASE_URL=http://localhost:8080
```

Android 模拟器访问宿主机时使用 `10.0.2.2`：

```powershell
flutter run -d emulator-5554 --dart-define=API_BASE_URL=http://10.0.2.2:8080
```

没有启动后端时，可在登录页选择“先用演示数据看看”。演示会话只用于检查界面和交互，不代表真实数据链路已验收。

小易冰箱当前使用 V1.5「暖橙食集」视觉：奶油底、陶土橙和暖木。Web 首页继续运行本地 Three.js/WebGL 2 几何厨房；启动前确认浏览器已开启硬件加速。3D 资源位于 `web/fridge3d` 和 `web/vendor`，不访问外部 CDN。模块使用 `warm-harvest-v1.5.1` 修订参数，修改静态资源发布时应同步更新缓存版本。主页面切换保留场景，隐藏或弹层打开时暂停交互/渲染。底部左门/右门/变温/冷冻按钮独立高亮，可同时开启。WebGL 不可用时显示明确状态，并保留食材清单；非 Web 端使用标明用途的暖橙参考图与真实清单。

界面内置带 OFL 许可证的 Xiaoyi UI 常用中文字库。重新制作字库可执行 `python scripts/Prepare-UiFonts.py --cache-dir <字体缓存绝对路径>`，需要 fontTools 和下载源字体的网络连接；覆盖 GB2312、当前界面及种子菜谱文字，生僻字或彩色 emoji 仍可能使用平台/引擎回退。

3D 交互验收路径：

1. 进入冰箱首页，确认暖木厨房、奶油色双门冰箱、三层玻璃搁板、双保鲜盒和门内瓶架；默认展开概览。
2. 拖动冰箱改变观察角度，确认视角有真实纵深且不会拖出视口。
3. 点击“全部关闭”，分别打开左右门，确认绕外侧铰链转动并共用冷藏内腔。
4. 点击变温、冷冻抽屉，确认沿轨道向前移动，变温浅托盘和冷冻双层篮可见；其他门与抽屉保留状态。
5. 切换 Flutter 分区按钮，确认区域标题与 3D 同步；常温区位于厨房侧台面。切换空冰箱家庭时，库存与模型食材均应清空；筛选清单不得改变完整场景库存。
6. 在 360 至 430 逻辑像素宽度下检查触控、文字和底栏，不允许横向溢出。

键盘聚焦模型后，数字 1–4 选择分区、0 恢复概览、Escape 关闭冰箱。自动化结构检查在仓库根执行 `node --test scripts/tests/fridge3d.test.mjs`。当前设计和实际截图见 [暖橙食集验收](design/warm-harvest/验收记录.md)。

## 5.1 容器化运行服务（端到端验收用）

基础设施用 core Compose 起好后，可把可执行 jar 放进 `eclipse-temurin:17-jre` 容器，与 MySQL/Redis 同网络运行，避免宿主机端口与进程干扰：

| 服务 | 关键环境变量 |
| --- | --- |
| auth-family | `MYSQL_CORE_URL`（容器内主机名 `mysql-core`）、`REDIS_HOST=redis`、`REDIS_PASSWORD` |
| fridge | 同上 MySQL，另加 `SMART_FRIDGE_AUTH_SERVICE_URL=http://sf-auth:8081` |
| recipe | `MYSQL_CORE_URL` 指向 `recipe_db` |
| gateway | **`AUTH_SERVICE_URL`（必填，否则令牌校验 503）**，以及 `AUTH_FAMILY_ROUTE_URI`、`FRIDGE_ROUTE_URI`、`RECIPE_ROUTE_URI`、`STOCK_ROUTE_URI`、`ORDER_ROUTE_URI`、`NOTIFICATION_ROUTE_URI` |
| stock/order/notification | 仅端口，无数据库依赖 |

网关默认把 `smart-fridge.auth-service-url` 指向 `http://127.0.0.1:8081`，在容器内这是它自己，必须显式覆盖，否则所有带令牌请求返回 503「认证服务暂时不可用」。

容器内的 MySQL 主机名用 `mysql-core` 而不是 `127.0.0.1`；连接串里的 `&` 需用引号包裹整个参数。

端到端验收脚本：

- `scripts/Smoke-ApiAudit.ps1`：全接口矩阵 135 项。
- `scripts/Smoke-FamilyWorkspace.ps1`、`scripts/Smoke-FoodFilters.ps1`：家庭协作 30 项、组合筛选 25 项。
- `scripts/Smoke-S3-TimelineCooking.ps1`：时间线、撤销/恢复、做饭幂等 29 项。
- `scripts/ui-acceptance-s3.mjs`：桌面视口（1414×807）UI 验收，需 `E2E_USER`、`E2E_PASS` 与 `UI_PLAN` 坐标；结果写入 `docs/reviews/evidence/2026-11-06-s3/`。

## 6. 验证命令

```powershell
cd backend
mvn test

cd ..\apps\fridge-app
dart analyze lib test
flutter test
flutter build web --release

cd ..\admin-web
npm run build

cd ..\..\infra\compose
docker compose --env-file .env.example -f compose.core.yml config --quiet
docker compose --env-file .env.example -f compose.full.yml config --quiet
```

Windows 中文路径下若 `flutter analyze` 触发 Analysis Server 的 JSON 路径异常，使用 `dart analyze lib test`；CI 在 ASCII 路径中仍执行 `flutter analyze`。

若本机设置了全局 HTTP 代理（`HTTP_PROXY` / `HTTPS_PROXY`），`flutter test` 启动的 `flutter_tester` 会经代理连接本地 WebSocket，表现为全部用例加载失败并报 `Invalid WebSocket upgrade request`。此时为本地地址放行，例如 Git Bash：

```bash
env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy \
  NO_PROXY=127.0.0.1,localhost no_proxy=127.0.0.1,localhost flutter test
```

这不是应用缺陷，恢复代理或用例本身后无需改代码。

完整构建 Flutter Web 与 Android APK：

```powershell
.\scripts\Build-Flutter.ps1
```

脚本会在系统临时目录建立纯 ASCII Junction，规避 Windows 中文路径下 Gradle/Dart AOT 的路径限制，并在结束后只移除 Junction，不删除源码或构建产物。

2026-10-31 本轮 Android 验收使用 ASCII 物理副本完成。若当前执行环境不允许 Junction，可把 `lib`、`assets`、`android` 和 pubspec 配置复制至独立 ASCII 构建目录，保持原 lock、package 配置和实际缓存版本一致，核对源文件哈希后运行 `flutter build apk --release --no-pub`；不要仅为规避路径问题升级工作区依赖。`android/gradle.properties` 已设置 `kotlin.incremental=false` 和 in-process 编译，以规避 Windows 跨盘 Kotlin 增量缓存。最终 APK、源码一致性和编译标签核对见 [本轮审查](reviews/2026-10-31-warm-harvest-xiaoyi.md)。

当前 `android/app/build.gradle.kts` 的 release 构建仍使用模板 debug 签名，生成包仅用于本地验收。正式分发前必须建立独立 release keystore，并通过环境变量或本机 `key.properties` 注入，禁止提交签名文件。

## 7. 停止与重建

保留数据停止容器：

```powershell
docker compose --env-file infra/compose/.env -f infra/compose/compose.core.yml down
```

需要彻底清空本地数据库、对象存储和中间件数据时，才能使用下面的破坏性命令：

```powershell
docker compose --env-file infra/compose/.env -f infra/compose/compose.core.yml down -v
```

该命令会删除本项目 Compose 的命名卷，无法通过 Git 恢复。

## 8. 常见问题

- `8848`、`3306` 或 `3307` 被占用：先检查本机是否已有 Nacos/MySQL，再调整 Compose 端口或停止冲突进程。
- Nacos 中看不到服务：确认 `SPRING_PROFILES_ACTIVE=cloud`、`NACOS_ENABLED=true`，并检查容器健康状态。
- Gateway 返回 503：确认目标服务已注册到 Nacos，服务名与路由 `lb://` 地址一致。
- Gateway 返回 401：登录接口以外的请求必须携带 `Authorization: Bearer <accessToken>`。
- 登出后访问家庭接口仍成功：确认 Redis 正常运行，访问令牌的 `jti` 应写入 `auth:revoked:{jti}`。

## 9. 家庭协作验证

家庭协作冒烟：

1. 用家庭 OWNER 登录并创建家庭。
2. 用第二个账号调用 `POST /api/v1/families/join` 输入邀请码。
3. 打开家庭页，确认目标家庭显示加入成功并可被选中。
4. OWNER 打开成员管理，将成员调整为 EDITOR。
5. 将该 EDITOR 设为所有权接收者，确认双方角色分别为 EDITOR 和 OWNER。

2026-10-30 已完成真实 Gateway/MySQL 双账号浏览器联调，证据见 [验收记录](reviews/2026-10-30-gateway-acceptance.md)。可在服务启动后使用 PowerShell 7 重跑接口验收：

.\scripts\Smoke-FoodFilters.ps1

## 10. 食材组合筛选

真实账号登录后，从冰箱首页“冰箱清单”或“清单”打开筛选面板。输入名称、完整分类、逗号分隔的多个标签，选择分区、到期状态、起止日期及排序，再点击“应用筛选”。“重置”恢复全部条件与默认排序，失败可重试。

接口为 `GET /api/v1/foods?fridgeId=...`；多个标签使用 `tags=早餐&tags=高蛋白`，所有条件同时满足。到期日期含首尾两天，采用冰箱时区；已过期为今天之前，临期为今天到三天后，新鲜为超过三天。默认最早到期优先，也支持最晚到期、名称升序和最近添加。筛选结果与首页总库存、WebGL 场景及菜谱库存快照独立；演示模式保留本地预览清单。

## 11. 全接口与普通交互复验

启动 core 基础设施及 7 个 Java 服务后，在仓库根执行：

```powershell
pwsh -NoProfile -File scripts/Smoke-ApiAudit.ps1
pwsh -NoProfile -File scripts/Smoke-FamilyWorkspace.ps1
pwsh -NoProfile -File scripts/Smoke-FoodFilters.ps1
```

全接口脚本要求 8080–8086 全部可用，涵盖健康、已有 ping、所有已落地业务入口及错误返回。输出不含令牌或密码，独立测试账号及数据保留供复查。商品、订单和通知仅验收当前已有骨架，尚不代表完整业务。

食材数量支持 0.001–999999999.999，最多三位小数；单个标签不能含逗号，标签去空格、去重并连接后的总长度最多 500。日期或 JSON 格式错误应返回 400，媒体类型错误应返回 415，不能误报 500。

浏览器交互验收须包含普通鼠标/触控路径：打开新增、实际填写并保存；点击生产/到期日期及下拉框；无临期结果时返回全部；创建/加入家庭、成员列表、设置说明可关闭。手机弹层必须盖住底栏，iframe 在所有覆盖弹层期间禁止接收点击。不可仅依赖可访问性代理点击或脱离 `HomeShell` 的 Widget 测试。

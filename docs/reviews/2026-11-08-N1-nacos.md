## 2. 变更清单

### 2.1 服务收敛：7 → 6

删除 `notification-service`。它原本只靠 RocketMQ 才有业务意义，消息队列冻结后就是纯空壳；P4“为什么这样拆”少一个要解释的服务。

同步清理的引用点：

- `backend/pom.xml` 的 `<module>`
- `gateway-service/application.yml` 的 `notification` 路由（`lb://notification-service`）
- `gateway-service/application-local.yml` 的固定地址路由与 `NOTIFICATION_ROUTE_URI`
- `scripts/Smoke-ApiAudit.ps1`：路由清单去掉 `notifications`，健康检查端口 `8080..8086` 改为 `8080..8085`

契约文件中本来就没有 `/api/v1/notifications/**` 路径，无需改动。

### 2.2 清理死代码

删除父 POM 中的 MyBatis-Plus 版本属性与 `dependencyManagement` 条目。8 个模块实际全部使用 `spring-boot-starter-data-jdbc` + `JdbcTemplate`，该依赖从未被任何模块引用。

### 2.3 注册发现真正启用

之前的状态是“容器起了、配置写了、但 `NACOS_ENABLED` 默认 `false`，网关走 `application-local.yml` 的固定地址”，Nacos 控制台里 0 个服务——属于评审明确不接受的“声明使用”。

改为：

- 6 个服务的 `spring.profiles.active` 默认值由 `local` 改为 **`cloud`**；
- `cloud` profile 已有 `spring.config.import: optional:nacos:${spring.application.name}.yaml?group=SMART_FRIDGE&refreshEnabled=true`，同时启用 discovery 与 config；
- 网关 `application.yml` 的路由保持 `lb://xxx-service`，成为默认路径；
- `application-local.yml` 保留为**降级模式**（无注册中心时按固定地址转发），仅在显式 `SPRING_PROFILES_ACTIVE=local` 时生效。

### 2.4 外置配置与动态刷新

新增 `fridge-service/config/FridgeSettings`：

```java
@Component
@RefreshScope
public class FridgeSettings {
    @Value("${smart-fridge.fridge.expiring-threshold-days:3}")
    private int expiringThresholdDays;
}
```

`FoodViewMapper` 中原本硬编码的 `remainingDays <= 3` 改为读取该值。这个改动同时修掉一处“硬编码业务常量”，对 D3（代码组织与实现质量）是正向的。

`application.yml` 增加本地兜底 `smart-fridge.fridge.expiring-threshold-days: ${EXPIRING_THRESHOLD_DAYS:3}`；Nacos 上的同名配置优先级更高，用于演示外置与刷新。

## 3. 发现的问题与处理

### 3.1 网关测试固化在旧 profile 上

`GatewayCorsTest.localProfileRoutesAllServicesWithoutNacos` 断言“6 条路由、scheme=http、host=127.0.0.1”，依赖默认 profile 是 `local`。默认切到 `cloud` 后该断言必然失败——这不是缺陷，而是测试把实现细节写死了。

处理：给该测试加 `@ActiveProfiles("local")`，断言改为 5 条路由（降级模式仍有价值，需要保留保障）；新增 `GatewayDiscoveryRouteTest`，用 `@ActiveProfiles("cloud")` 断言 5 条路由全部是 `lb://xxx-service`。两个 profile 的行为现在都有测试覆盖。

### 3.2 冒烟脚本的端口范围与路由清单

`Smoke-ApiAudit.ps1` 硬编码了 `8080..8086` 与 `notifications` 路由。删除服务后脚本直接抛 `ConvertFrom-Json` 解析失败（8086 无响应返回空体）。已改为 `8080..8085` 与 4 条业务路由，复跑 **132/132 通过**（原 135 项减去 notification 的健康检查、ping、无令牌 401 各 1 项）。

### 3.3 Nacos 通过表单提交多行 YAML 会被破坏

第一次用 `POST /nacos/v1/cs/configs` 的 form 方式提交多行 YAML，读回内容是 `a:/n  b: 1`——换行符被存成了字面 `/n`，配置解析失败，导致刷新看起来“不生效”。

```
$ curl ... --data-urlencode $'content=a:\n  b: 1\n'
$ curl ... /nacos/v1/cs/configs?dataId=probe.yaml
a:/n  b: 1
```

规避方式：配置内容改用**单行 flow-style YAML**，不依赖换行：

```
{"smart-fridge": {"fridge": {"expiring-threshold-days": 10}}}
```

这也是验收脚本 `scripts/Smoke-Nacos.ps1` 采取的方式，后续所有 Nacos 配置写入都应遵循。

### 4.3 汇报可用的话术

| 被问 | 回答要点 |
| --- | --- |
| 服务怎么被找到 | 启动时向 Nacos 注册 `服务名 → IP:端口`；网关拿 `lb://fridge-service` 向注册中心要健康实例列表，再按负载均衡选中一个 |
| 某个服务没注册会怎样 | 网关 503（无可用实例）；日志能看到 `Unable to find instance for xxx-service`；处理顺序是先看服务是否启动、再看注册是否成功、最后看网络与命名空间分组 |
| 配置为什么能被刷新 | `spring.config.import` 拉取配置并注册监听；Nacos 推送变更后发布 `RefreshEvent`，`@RefreshScope` 的 bean 被销毁重建，下次调用读到新值 |
| 什么不能热刷新 | 数据源 URL、连接池大小、`spring.config.import` 本身这类在启动期参与 Bean 创建的配置；它们需要重启，或走 `@RefreshScope` 之外的重建策略 |

## 6. 复现方式

```powershell
# 1. 基础设施
cd infra\compose
docker compose --env-file .env.example -f compose.core.yml up -d

# 2. 6 个服务（以 fridge 为例，其余替换 jar、端口与库名；stock/order 无数据库依赖）
docker rm -f sf-fridge
docker run -d --name sf-fridge --network smart-fridge -p 8082:8082 `
  -e NACOS_ADDR=nacos:8848 `
  -e "MYSQL_CORE_URL=jdbc:mysql://mysql-core:3306/fridge_db?useSSL=false&characterEncoding=utf8" `
  -e MYSQL_CORE_USER=smart_fridge -e MYSQL_CORE_PASSWORD=smart_fridge_dev `
  -e SMART_FRIDGE_AUTH_SERVICE_URL=http://sf-auth:8081 `
  -v "<repo>/backend/fridge-service/target/fridge-service-0.1.0-SNAPSHOT.jar:/app/app.jar:ro" `
  eclipse-temurin:17-jre java -jar /app/app.jar
# 网关另需 -e AUTH_SERVICE_URL=http://sf-auth:8081

# 3. 外置配置（注意：单行 flow-style，form 提交多行会被存成 /n）
curl -X POST "http://127.0.0.1:8848/nacos/v1/cs/configs" `
  --data-urlencode "dataId=fridge-service.yaml" `
  --data-urlencode "group=SMART_FRIDGE" `
  --data-urlencode "type=yaml" `
  --data-urlencode 'content={"smart-fridge": {"fridge": {"expiring-threshold-days": 10}}}'

# 4. 验收
.\scripts\Smoke-Nacos.ps1
.\scripts\Smoke-ApiAudit.ps1
```

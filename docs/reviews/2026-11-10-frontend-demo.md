审查覆盖上述新增源文件的完整内容与本次差异，重点检查权限、家庭数据隔离、异步路径、失败恢复及兼容性。开始工作前已读取开发状态、根目录 AGENTS.md 和工作区状态。现有 V2.0 正式应用、后端与其他既有未提交差异没有在本次修改；历史阶段的验证不能替代本次结果。

## 功能与正确性检查

- 五个页面：冰箱、食材、菜谱、家庭、操作记录；响应式侧栏和手机底部导航。双门与两抽屉独立开合，场景复位及分区入口可操作。
- 食材新增、编辑、使用、移动、丢弃及清理使用当前家庭数据。写入在克隆状态上执行并校验，通过后统一发布；只读在界面与处理函数两处检查。前端权限仅为演示，不作为真实鉴权。
- 新建家庭与空家庭独立存储；加入演示家庭获得只读身份。成员操作仅修改本地数据，不发送消息。
- 做饭重新计算所需库存，排除过期食材；同名、同单位的多个批次按到期先后扣减。缺料时禁用确认；统一扣减避免出现只扣了一部分食材的状态。
- 撤销和恢复要求当前库存与对应快照一致，不能覆盖后续库存变化。导出只包含当前家庭的演示数据。
- 表单校验正数、两位小数、名称长度和购入/到期日期顺序。失败保留输入；草稿关闭和危险操作需要确认；用户文本转义后显示。
- 独立 localStorage 命名空间，不读取真实会话。损坏数据恢复初始示例并提示；存储写入失败时继续保留当前页面数据，明确说明刷新后可能丢失。
- 多标签页检测到存储版本变化后暂停旧页面写入，包括设置和撤销；提供刷新载入。这个本地保护不等同于数据库锁或真实多人同步。
- 唯一异步业务外路径是复制邀请码的浏览器剪贴板调用，有无法自动复制时的选中提示；下载使用本地 Blob，并释放 Object URL。没有后端或第三方请求。
- 新演示不调整正式产品接口；厨房使用 CSS 动画，内部食材是装饰示意，已在页面及说明中标注。

## 发现与修复

1. 初次脚本在非空收藏列表查找仅空结果才显示的按钮而中断。修正驱动为点击实际存在的“全部菜谱”筛选，不属于产品功能缺陷。原始结果保留在 `browser-review-first.json`。
2. 演示邀请码原为 9 位，但输入和 schema 约束为 8 位，导致示例无法加入。统一改为 **SUNN2026**，通过加入、只读控制及家庭隔离回归。修复前结果保留在 `browser-review-second.json`。
3. Escape 自动化路径未弹出草稿确认。增加明确的 Escape 键盘处理，并在驱动中提供虚拟键码，保留原生 dialog cancel 处理；回归通过。该现象不作为旧版本人工按键必然失败的证明。修复前结果保留在 `browser-review-third.json`。
4. 审查发现仅提示另一标签页更新仍可能允许旧页面覆盖数据。补充写入前版本检测、暂停写入与刷新入口；已验证库存及偏好设置均不会覆盖检测到的新数据。
5. 视觉检查发现关闭门缝偏大、品牌容器在图标初始化时被替换；调整门宽并保留品牌容器，最终截图已复核。

# 用户业务与课程组件落地复核（2026-11-08）

## 复核范围与结论

复核当前 Flutter 家庭创建、食材入库、做饭流程，auth/fridge 的真实调用，N1–N4 的实现与证据，以及管理端订单页。工作区初始版本为 `1d9ba11`，无未提交差异。

- 家庭冰箱的补货是食材入库，不涉及购买、支付或订单。
- Feign 已用于 fridge → auth 的家庭权限检查；SkyWalking 已挂载真实业务服务。先前将所有组件概括为订单演示是不准确的。
- Sentinel 与 Seata 的专项验收主要依赖独立的 order/stock 链路；管理端订单页为静态示例，也没有调用该后端。它们不能作为家庭冰箱用户业务已经集成这些组件的证据。
- 旧 N1–N4 的历史技术验证保留，但撤回“课程组件已全部完成用户业务落地、仅剩收尾”的整体结论。

## 修正方向与验收门槛

围绕现有家庭引导增加“创建家庭并初始化默认冰箱”的一次性操作。账号/家庭/成员仍由 auth 服务管理，冰箱/分区/容器仍由 fridge 服务管理，保留自然的数据归属。旧的单独创建家庭、创建冰箱 API 保持兼容。

1. 用户端真实提交触发 Feign 按服务名调用；传递真实访问令牌和全局事务 XID。
2. Sentinel 保护创建入口及冰箱初始化依赖；权限拒绝、参数错误与系统故障分别处理，依赖不可用时不得伪造创建成功。
3. Seata 保证家庭/OWNER 成员与默认冰箱一起创建或一起回滚。请求幂等、用户隔离、并发重试和提交状态必须验证。
4. SkyWalking 从真实家庭创建请求捕获跨服务链路，覆盖正常与异常流程。
5. 运行自动化、真实 MySQL/Seata 验证（成功与失败各至少两例），再进行 Web 交互验收。Android 真机未实际执行时单独标记。

本记录是范围复核，不是改造验收通过记录。实现后须再次审查完整工作区 diff，修复影响正确性的缺陷，记录本轮命令与结果。

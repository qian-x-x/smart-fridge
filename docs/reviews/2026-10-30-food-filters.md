# S2 食材组合筛选与排序审查

日期：2026-10-30。前置阶段已通过 [真实环境验收](2026-10-30-gateway-acceptance.md) 后进入本阶段。

## 实现范围

- 扩展现有 `GET /api/v1/foods`，保留只传 fridgeId/query 的调用方式与默认到期升序。
- 名称字面包含、完整分类、全部标签、分区、到期状态、含边界的起止日期均以 AND 组合；排序支持最早到期、最晚到期、名称、最近添加，同值按 ID 升序。
- 到期状态使用冰箱时区与服务端 Clock：已过期 < 今天；临期为今天至三天后；新鲜 > 三天后。
- Flutter 真实账号从首页清单入口打开筛选面板，支持应用、重置、错误重试、结果为空和详情操作；演示模式保留原本地预览。
- 查询结果使用独立 FutureProvider，完整冰箱快照继续用于首页、3D 场景与菜谱，不被筛选覆盖。

## 审查与修复

- 所有查询先核实冰箱所属家庭权限，SQL 固定限制 fridge_id 和 ACTIVE；zoneId 不能扩大查询范围。
- SQL 值全部使用参数绑定；排序只有枚举白名单；名称及标签中的 `%`、`_`、`!` 做字面转义。
- 标签按逗号边界匹配完整项，多标签逐项 AND；Dio 显式发送重复 tags 参数，避免默认方括号格式与 Spring 绑定不兼容。
- 枚举、正数分区、字段长度、日期格式与日期顺序有后端校验，非法参数返回 400；前端另做可读提示。
- 每次应用使用独立查询实例，旧请求不覆盖新查询；请求携带原冰箱 ID，家庭切换后不能误查询其他工作区。
- 浏览器发现重置时 DropdownButtonFormField 会通过 onChanged 恢复旧初值，导致到期条件残留。已调整 Form.reset 与默认状态赋值的顺序，并增加“选择临期后重置必须发送 ALL”的回归断言。

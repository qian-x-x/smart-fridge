# S2 冰箱领域实现

## 当前范围

S2 后端第一纵切由 `fridge-service` 提供，客户端仍统一从 Gateway `8080` 访问。

| 能力 | 路径 | 权限 |
| --- | --- | --- |
| 创建冰箱与默认四区 | `POST /api/v1/fridges` | OWNER |
| 查询冰箱结构 | `GET /api/v1/fridges/{fridgeId}` | 家庭成员 |
| 按家庭查询冰箱 | `GET /api/v1/fridges?familyId={familyId}` | 家庭成员 |
| 查询/搜索食材 | `GET /api/v1/foods` | 家庭成员 |
| 新增食材 | `POST /api/v1/foods` | OWNER、EDITOR |
| 食材详情 | `GET /api/v1/foods/{foodId}` | 家庭成员 |
| 编辑食材 | `PUT /api/v1/foods/{foodId}` | OWNER、EDITOR |
| 移动食材 | `POST /api/v1/foods/{foodId}/move` | OWNER、EDITOR |
| 使用食材 | `POST /api/v1/foods/{foodId}/consume` | OWNER、EDITOR |
| 丢弃食材 | `DELETE /api/v1/foods/{foodId}?version={version}` | OWNER、EDITOR |

## 数据与一致性

- 每个家庭只有一个冰箱，创建后自动生成 `FRESH`、`VARIABLE`、`FREEZER`、`PANTRY` 四个分区。
- 食材必须归属有效冰箱和分区；容器存在时必须归属该分区。
- 食材写操作使用 `version` 乐观锁。版本不一致返回 `CONFLICT`，客户端应刷新后重试。
- 使用数量不能超过剩余数量，数据库同时以非负约束保护数量。
- 丢弃为软删除：食材状态变为 `DISCARDED`，历史操作保留。
- `food_operation` 记录操作人、前后分区、前后容器、前后数量和时间。
- 临期阈值当前固定为 3 天；冰箱时区和阈值配置在后续纵切落地。

## 服务间鉴权

1. Gateway 校验 access token，并向下游写入 `X-User-Id`、`X-User-Name`。
2. `fridge-service` 要求所有业务请求携带网关用户头。
3. 每次家庭数据访问都通过 OpenFeign 携带原访问令牌调用认证家庭服务，实时取得当前家庭角色。
4. 下游不接受仅由客户端请求头声明的家庭角色。

## 测试覆盖

`FridgeApiIntegrationTest` 使用 H2、Flyway 和 MockMvc，并以本地 HTTP 服务模拟认证家庭接口。当前覆盖：

- 缺少用户身份、OWNER 创建、VIEWER 禁止创建。
- VIEWER 查询冰箱与食材。
- OWNER/EDITOR 新增食材和操作日志。
- 名称搜索、移动、使用、超额使用拒绝、编辑和软删除。
- Flutter 真实家庭/冰箱/食材映射与首屏替换演示数据。
- Flutter 新增、使用、移动、丢弃及加载失败重试。
- Flutter 过期 access token 自动刷新、刷新失败回登录页。

## 菜谱接口

- `GET /api/v1/recipes` 返回 MySQL 中的菜谱目录。
- `GET /api/v1/recipes/{recipeId}` 返回原料、可选标记和步骤。
- Flutter 使用当前冰箱食材在客户端计算匹配度、缺少项和临期优先顺序。
- 当前目录包含 6 道 Flyway 种子菜谱，做饭扣减尚未实现。

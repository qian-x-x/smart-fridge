选型依据

  • 课程要求覆盖微服务、网关、注册中心、分布式事务与消息队列，故按业务能力划分服务，而非按页面划分。
  • 三维冰箱以 Flutter Web 内嵌 Three.js 场景实现，较纯 Dart 建模成本更低。
  • 七个服务共用父 POM 与统一响应结构，新增服务仅需实现业务逻辑。
  • 中间件先保证本机可启动，再逐步接入真实业务，避免仅存配置而无运行证据。

标注口径

已接入：具备接口、数据表与联调记录
仅配置：仅含容器编排与依赖，无业务调用
骨架服务不计入已完成范围
待补齐 Seata 回滚与 MQ 消费证据

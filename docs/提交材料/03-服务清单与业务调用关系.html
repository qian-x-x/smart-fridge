④ 业务调用关系

登录 / 续期 Flutter→ Gateway :8080→ auth :8081→ MySQL 账号+ Redis 刷新会话 返回 access + refresh，refresh 一次性轮换
录入食材 Flutter→ Gateway 验签 + 撤销校验→ fridge :8082→ auth 取家庭角色→ MySQL 写入 + 流水 VIEWER 在此被拦成 403
查看菜谱 Flutter→ Gateway :8080→ recipe :8083→ MySQL 菜谱目录 覆盖率在客户端按库存本地计算，不跨服务
创建冰箱 Flutter→ Gateway :8080→ fridge :8082→ auth 确认 OWNER→ MySQL 冰箱 + 四区 一个家庭只允许一台冰箱，重复创建返回 409
路由映射 · GATEWAY ROUTES
/api/v1/auth/**, /families/**→ auth-family :8081
/api/v1/fridges/**, /foods/**→ fridge :8082
/api/v1/recipes/**→ recipe :8083
/api/v1/products/**, /orders/**→ stock / order

调用路径说明

  • 客户端请求统一经网关转发，不直连 8081–8086。
  • 仅存在两条跨服务调用：冰箱与菜谱服务回查认证服务的家庭角色，方向单一且无环。
  • 深色标注为网关的验签与撤销校验，属每笔请求的必经环节。
  • 菜谱服务不反向调用冰箱服务，原料匹配在客户端完成。

核对项

每条链能指出在哪一步做权限校验
跨服务调用不超过必要次数
失败时返回 401 / 403 / 404 而不是 500
补货链（库存→订单→通知）尚未联通

并发与幂等

  • 写操作携带 version，冲突返回 409，由前端刷新后重试。
  • refresh 令牌为一次性消费，重复使用即失效。
  • 重复加入家庭返回已有角色，不产生重复成员。

# V1 写实厨房与冰箱界面重构

日期：2026-10-31。替代 V1.3 的香槟复古视觉条款，业务接口、角色和数据隔离保持现有契约。依据用户选定的 `docs/design/realistic-fridge/fridge-concept-v1.png` 与 `fridge-kitchen-v1.png`，PSD 是单图层视觉参考，不作为 3D 模型或 UI 代码。

## 视觉与结构

- 银色拉丝不锈钢冰箱、白色内胆、灰色密封条、透明玻璃层架、左右门内瓶架、双保鲜盒、中部浅变温抽屉和下部双层冷冻篮。
- 按约 900 × 1850 × 720 mm 比例建立实时模型；门沿侧铰链转动，抽屉沿轨道平移，内腔是开放壳体，避免旧模型的实心外壳遮挡。
- 上部左右门均属于冷藏。常温食品位于厨房侧柜台，不能标注在冷藏门内。
- 厨房包含木色橱柜、石材台面、窗户、浅色墙砖、地面、自然日光与接触阴影，厨房和冰箱使用同一实时场景与相机。
- 食材几何来自当前快照；真实空冰箱不放置演示食材。每个简化几何代表一条记录而非精确数量，正式食材扫描资产不在本轮范围。

## 界面

- 白色/石材灰界面、深灰文字、木色辅助、绿色操作强调；统一圆角 8–16 px，减少装饰圆球、贴纸和胶囊堆叠。
- 桌面使用侧导航、页面标题、宽厨房视口和库存侧栏；移动端保留底导航、完整模型和下方库存清单。
- 保留登录、注册、家庭创建与加入、角色管理、选择持久化、组合筛选、食材增改移用丢、菜谱匹配和错误重试。视口控制不写入业务数据。
- 业务摘要只读真实快照；温度属于储存参考，不宣称传感器实时测温；移除硬编码菜谱匹配百分比。
- WebGL 不可用时显示明确降级状态；非 Web 客户端使用 V1 参考图与同数据清单，不伪称实时 3D。

## 审查与验收

上一阶段的组合筛选审查与真实环境证据已阅读，无阻止视觉重构的缺陷；历史 Flutter 焦点异常继续保留观察记录。

1. 模型结构、铰链/滑轨、常温语义与状态机通过自动化检查及浏览器检查后，继续 UI 集成。
2. 用户端静态分析、回归测试、Web 构建通过；浏览器检查桌面与 390 px 页面、模型展开/关闭、抽屉、分区、真实数据和空状态。
3. 最终审查记录与开发状态同步，更新工程设计和 V1.4 Word 说明；文档渲染逐页检查后交付。

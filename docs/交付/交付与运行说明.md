## 当前可用范围

- Flutter Web真实用户功能：注册登录、家庭协作、创建家庭及默认冰箱、食材管理、时间线撤销恢复、菜谱匹配和做饭扣减。
- 日常后端：gateway、auth-family、fridge、recipe。默认不启动历史order和stock。
- 正式入口为Flutter用户端；管理端原型已移出有效工程。用户补货指食材入库，不购买或下单。
- 2026-11-09已有验收：后端86项、Flutter92项、真实API223项、浏览器10项通过，成功和失败追踪各一条。详细结果保存在源码的 `docs/reviews/2026-11-09-real-family-workspace.md`。
- 尚未验收：Android真机、正式release签名、持续容量压测和高可用。新电脑需要重新验证，历史结果不等于接收环境已通过。

## 接收电脑准备

以Windows和PowerShell7为主要交付环境，安装Docker Desktop、JDK17、Maven3.9、Flutter3.47.8及其Dart3.13.7。辅助验收脚本需要Node.js22；构建Android还需Android SDK、命令行工具及已接受的许可证。Chrome或Edge需要支持WebGL2。

推荐把源码解压到没有中文和空格的短路径，例如 `C:\Projects\xiaoyi-fridge`，避免Android原生工具的路径兼容问题。预留足够磁盘与Docker内存；原验收机Docker约5.8GiB内存，通过四服务逐个启动运行，不代表容量基准。不要同时启动日常与隔离验收的全部JVM。

在PowerShell7中进入源码根目录，后面的命令均从这里执行。可先检查：

```powershell
java -version
mvn -version
flutter --version
docker version
```

## 首次启动真实业务依赖

以下用于新接收环境。已有同名容器时先检查 `docker ps -a` 和原运行手册，不要删除数据卷或覆盖现有配置。

```powershell
# 只启动当前家庭业务依赖；交易库和Sentinel控制台按演示需要选择。
docker compose --env-file infra/compose/.env.example `
  -f infra/compose/compose.full.yml up -d `
  nacos mysql-core redis seata skywalking-oap skywalking-ui

docker compose --env-file infra/compose/.env.example `
  -f infra/compose/compose.full.yml ps
```

等待MySQL、Redis和Nacos健康，Seata与SkyWalking启动完成。Nacos页面在 `http://127.0.0.1:8848/nacos`，SkyWalking在 `http://127.0.0.1:8088`。示例配置是本地课程环境，不能直接作为公网部署配置。

## 准备SkyWalking Agent

源码不携带Agent二进制。首次从指定镜像导出，以下临时容器仅用来复制文件，不会启动服务：

```powershell
New-Item -ItemType Directory -Force infra/skywalking | Out-Null
$deliveryAgentContainer = docker create apache/skywalking-java-agent:9.6.0-java17
if ($LASTEXITCODE -ne 0) { throw '创建Agent复制容器失败' }
try {
  docker cp "${deliveryAgentContainer}:/skywalking/agent" infra/skywalking/agent
  if ($LASTEXITCODE -ne 0) { throw '复制Agent失败' }
} finally {
  docker rm $deliveryAgentContainer | Out-Null
}
Copy-Item infra/skywalking/agent/optional-plugins/apm-spring-cloud-gateway-4.x-plugin-9.6.0.jar infra/skywalking/agent/plugins/
Copy-Item infra/skywalking/agent/optional-plugins/apm-spring-webflux-6.x-plugin-9.6.0.jar infra/skywalking/agent/plugins/
```

已有 `infra/skywalking/agent/skywalking-agent.jar` 时无需重复复制。Agent未准备好时启动脚本会警告并省略追踪；业务可启动不代表SkyWalking已生效。

## 构建并启动后端

```powershell
Push-Location backend
try {
  mvn test
  if ($LASTEXITCODE -ne 0) { throw '后端测试失败' }
  mvn -DskipTests package
  if ($LASTEXITCODE -ne 0) { throw '后端打包失败' }
} finally { Pop-Location }

.\scripts\Start-Services.ps1 -SkipBuild
```

脚本按顺序启动四个应用，等待各自健康。首次启动时Flyway自动创建业务表和种子菜谱，不需要导入本机数据库快照。服务端口为8080至8083；脚本目前按公开的开发示例账号连接数据库，自定义凭据时要同步调整Compose和服务环境变量。

查看健康状态：

```powershell
8080..8083 | ForEach-Object {
  Invoke-RestMethod "http://127.0.0.1:$_/actuator/health"
}
```

## 启动用户端Web

可以重新构建，也可以使用包内Web产物。以下先介绍从源码构建，保持pubspec.lock，不执行升级：

```powershell
Push-Location apps/fridge-app
try {
  flutter pub get --enforce-lockfile
  if ($LASTEXITCODE -ne 0) { throw 'Flutter依赖安装失败' }
  flutter build web --release --no-pub
  if ($LASTEXITCODE -ne 0) { throw 'Web构建失败' }
} finally { Pop-Location }
.\scripts\Start-Web.ps1
```

打开 `http://127.0.0.1:3030`。Nginx把 `/api/` 同源代理到网关，因此无需改网页内的IP。直接双击index.html无法完成真实业务。

如复用预构建产物，把 `artifacts/小易冰箱-Web.zip` 的内容解压到源码 `apps/fridge-app/build/web/`，确保这个目录下直接有index.html，再运行 `Start-Web.ps1`。该操作只代替Web编译，后端与依赖仍要启动。

仅开发调试也可运行 `flutter run -d chrome --dart-define=API_BASE_URL=http://127.0.0.1:8080`。局域网浏览器访问按开发运行手册配置3000端口转发；接手电脑的IP与本机不同，需要重新确认。

## Android测试包说明

包内APK的API地址在构建时固定为 `http://192.168.10.225:8080`，这是原验收机地址。它不适用于任意接收电脑；本轮没有真机验收，不把APK作为免配置成品。Android当前使用厨房参考图，Web使用交互式Three.js三维场景。

需要在新电脑联调时，连接手机并确认同一网络、后端端口可访问，然后用新电脑实际局域网IP重新构建：

```powershell
Push-Location apps/fridge-app
try {
  flutter build apk --release --no-pub `
    --dart-define="API_BASE_URL=http://<接收电脑实际局域网IP>:8080"
} finally { Pop-Location }
```

把尖括号占位内容替换为实际IPv4地址再运行。输出为 `build/app/outputs/flutter-apk/app-release.apk`。当前Android工程仍使用模板debug签名；正式发布需接手人配置自己的签名，并完成真机和联网验收。

## 建议的接收验收

1. 四个业务服务健康，Nacos有四个正常实例。
2. 注册一个新账号；本包没有固定的真实用户账号或原数据库。
3. 创建家庭，回到首页确认默认冰箱已出现，不需要额外购买或下单。
4. 新增食材并重新加载，确认真实保存；尝试编辑、移动、使用和查询记录。
5. 邀请第二个账号，验证VIEWER只读，再按需调整EDITOR。
6. 打开菜谱，完成一次选定食材的做饭扣减，并观察时间线。
7. 在SkyWalking查看新产生的创建家庭链路。

需要自动化兼容检查时运行 `scripts/Smoke-ApiAudit.ps1`。它会注册账号和创建数据，请使用独立验收环境。新家庭故障验收使用 `Start-BusinessAcceptance.ps1`、`verify-family-workspace.py`等，完整步骤见阶段审查，不与日常全部服务同时运行。

## 常见问题

| 现象 | 首先检查 |
| --- | --- |
| 创建家庭503 | Seata8091、fridge健康、Nacos实例、熔断窗口和服务日志 |
| 页面能开但API失败 | 后端是否运行，Nginx是否与sf-gateway在同一网络 |
| 401 | 没登录、令牌过期或已撤销；重新登录 |
| 403 | 当前账号不是该家庭成员或没有编辑权限 |
| 409 | 数据版本已变化、重复请求意图不一致或初始化仍在处理 |
| 429 | 请求频率超过规则，稍后重试 |
| 三维场景不可用 | WebGL2和显卡支持；切换表格清单查看同一份数据 |
| 手机无法访问 | 手机不能用127.0.0.1访问电脑；核对IP、网络及电脑端口访问 |
| SkyWalking没有新链路 | Agent是否加载、OAP是否可用、查询时间和时区是否正确 |
| Android编译失败 | 先尝试ASCII短路径，核对SDK、JDK、锁文件和网络 |

## 版本和完整性

交付目录中的 `manifest.json` 记录源码Git提交号；源码内包含本说明。`SHA256SUMS.txt`记录每份文件的SHA256，收到后可用 `Get-FileHash -Algorithm SHA256 <文件>` 核对。源码ZIP的每个文件还会与对应Git blob核对；PowerShell和批处理文件按Git声明的CRLF行尾规范化后比较，清单记录这些路径，确保来自指定提交。

ZIP不含Git历史，如需继续保留版本历史应另行交接仓库。本节描述原交付机制；本轮功能收敛未提交、推送或重新打包，也没有部署到外部服务器。

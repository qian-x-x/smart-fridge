#### S3 操作时间线与做饭扣减

- `GET /api/v1/fridges/{fridgeId}/operations` 返回按时间倒序的操作流水，支持 `foodId` 过滤与 1—100 条上限；每条带 `undone`、`undoable` 与 `revertedByOperationId`。
- 新增 `POST /api/v1/foods/{foodId}/operations/{operationId}/undo` 与 `.../restore`。仅移动、使用、做饭扣减、丢弃可撤销；撤销写入 `UNDO` 流水并回填原操作，恢复写入 `RESTORE` 流水并清空标记，同一操作可反复撤销/恢复。`ADD`/`UPDATE` 因原始字段不足而明确返回 409。
- 撤销使用行锁加 `reverted_by_operation_id` 条件更新，同一操作并发撤销只有一个成功；食材版本可选传入，不一致返回 409。
- 新增 `POST /api/v1/fridges/{fridgeId}/cook-records`：按菜谱与份数提交扣减清单，逐条校验归属、数量与版本后在同一事务内扣减并写 `COOK` 流水与做饭记录；`(fridge_id, request_id)` 唯一约束保证重放不重复扣减，重放返回 200、首次返回 201。
- `GET /api/v1/fridges/{fridgeId}/cook-records` 返回做饭记录与明细（食材名称、数量、单位快照）。
- 新增 `V3` 迁移：`food_operation.reverted_by_operation_id`、`cook_record`、`cook_record_item`。
- Flutter 库存面板新增“记录”入口与时间线弹层（撤销/恢复、只读成员隐藏按钮、加载/空/失败状态）；菜谱详情新增“用现有食材做这道菜”，弹层内可勾选食材并以 0.5 步进调整数量。
- 抽出 `FridgeAccessGuard` 统一冰箱与家庭角色校验，`FoodViewMapper` 统一到期天数口径。

### 2026-11-08 N3 Seata 跨服务事务

- **交易库落地**：新增 `infra/mysql/trade/002_trade_tables.sql`，建 `stock_db.stock_item`、`order_db.order_record` 与两个库各自的 `undo_log`。库存与订单分库，跨库才需要全局事务。

- **下单开启全局事务**：`OrderService.create` 上 `@GlobalTransactional + @Transactional`，顺序是「写 PENDING 订单 → 远程扣库存 → 成功才标记 CREATED」。失败一律抛异常而不是返回失败值，否则已写入的订单会被提交。新增 `failAfterDeduct` 演示参数。
- **XID 传播**：`SeataFeignConfig` 显式把 `RootContext.getXID()` 写入 `TX_XID` 头。自动集成失效时的表现是“库存扣了但回滚不了”且不报错，显式拦截器让这件事可读。
- **两种回滚路径**：订单的插入在本地事务内、随异常一起回滚（不注册分支）；库存的扣减已在一阶段提交，由 TC 下发 `BranchRollbackRequest` 用 undo_log 还原。这条差异是本轮最值得讲的机制点。

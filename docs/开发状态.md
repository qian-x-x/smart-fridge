## 已完成

### S0 工程决策

- 技术栈、服务边界、课程组件、核心业务闭环、验收映射和阶段计划已冻结。
- 项目所有者与实施方为同一人，不依赖外部合同签署或协作权限。
- V1.2 开发说明保留原文件，V1.3 作为当前产品、视觉和验收基线。

### S1 工程底座

- Flutter Android/Web 用户端可构建，包含登录、注册、安全会话、演示入口、菜谱和个人页。
- Vue 3 运营端可构建，包含登录、仪表盘、菜谱、库存和订单演示页面。
- Java Maven BOM 与 7 个 Spring Boot 服务模块可编译、测试和运行。
- 认证家庭服务已完成注册、登录、JWT 刷新轮换、登出撤销、家庭创建和 OWNER 成员关系。
- Gateway 统一路由、CORS、健康检查、请求追踪头及循环回环地址适配已完成。
- MySQL 双实例、Redis、Nacos、MinIO 的 core Compose 可启动。
- full Compose 包含 RocketMQ、Seata、Sentinel、SkyWalking 配置，尚未形成真实业务证据。

### WebGL 真 3D 升级

- 用户端冰箱首页已由 2.5D 分层图改为 Three.js/WebGL 2 实时 3D。
- 模型包含上方 French door、中部变温抽屉、下部冷冻抽屉、厚门体、铰链、拉丝金属外壳、内部层架和食材几何体。
- 支持拖拽环绕、射线拾取、门体开合、抽屉拉出和 Flutter 分区状态同步。
- 桌面布局包含左侧导航、中央 3D 舞台和右侧状态面板；移动端以冰箱作为首屏第一视觉。
- Three.js 运行文件已本地打包并保留许可证，不依赖 CDN。
- WebGL 不可用时显示明确错误态，并提供同数据表格清单。
- V1.3 开发说明已增加视觉基线、状态与验收矩阵、桌面和移动端概念图。

## 下一阶段

S2 按以下顺序实施：

1. 在 `fridge-service` 建立冰箱、区域、储物容器、食材、移动记录和操作撤销模型。
2. 通过 Gateway 提供经 JWT 与家庭权限校验的食材 CRUD、搜索、筛选和表格查询 API。
3. Flutter 接入真实 API，用服务端数据驱动 3D 分区、食材详情、新增、移动和降级清单。
4. 增加 Flyway 迁移、集成测试、契约测试和浏览器端真实数据验收。
5. 在 S2 完成后再替换正式食材模型，不在业务闭环未完成前扩展纯装饰素材。

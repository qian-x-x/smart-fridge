- 模型包含上方 French door、中部变温抽屉、下部冷冻抽屉、厚门体、铰链、拉丝金属外壳、内部层架和食材几何体。
- 支持拖拽环绕、射线拾取、门体开合、抽屉拉出和 Flutter 分区状态同步。
- 桌面布局包含左侧导航、中央 3D 舞台和右侧状态面板；移动端以冰箱作为首屏第一视觉。
- Three.js 运行文件已本地打包并保留许可证，不依赖 CDN。
- WebGL 不可用时显示明确错误态，并提供同数据表格清单。
- V1.3 开发说明已增加视觉基线、状态与验收矩阵、桌面和移动端概念图。

### S2 冰箱领域第一纵切

- `fridge-service` 已接入 MySQL/Flyway，新增 `fridge`、`fridge_zone`、`fridge_container`、`food_item` 和 `food_operation` 表。
- 家庭 OWNER 可创建冰箱，系统自动生成冷藏、变温、冷冻和常温四区及默认储物容器。
- OWNER、EDITOR、VIEWER 均通过认证家庭服务实时校验家庭角色；VIEWER 的写操作由后端返回 403。
- 食材支持新增、详情、名称搜索、整体编辑、移动、使用扣减和软删除，并按家庭隔离。
- 食材数量使用 `version` 乐观锁；数量禁止为负；临期阈值当前固定为 3 天。
- 新增、编辑、移动、使用和丢弃均追加不可删除的 `food_operation` 记录。
- OpenAPI 已补充冰箱与食材接口及请求模型。

### S2 Flutter 真实数据纵切

- 新增按家庭查询冰箱的 `GET /api/v1/fridges?familyId=` 接口。
- Flutter 登录会话会通过 Gateway 加载当前家庭的冰箱、分区和食材，不再用演示数据覆盖真实首页。
- access token 临近过期或旧会话缺少签发时间时自动刷新并持久化新令牌；refresh token 失效后清除会话并返回登录页。
- WebGL 分区、顶部摘要、状态栏、临期列表、详情弹层和降级表格共享同一份服务端快照。
- 新增食材表单已真实写入后端，支持名称、分类、数量、单位、区域和日期。
- 食材详情支持使用、移动和丢弃；所有写操作携带当前 `version`，冲突时保留页面数据并提示刷新重试。
- 提供加载、失败重试、空食材、只读权限和无分区状态。
- 演示账号继续使用本地演示数据，并禁止写入真实冰箱。

### S2 家庭与菜谱接口纵切

- 家庭页通过 `GET /api/v1/families` 显示真实家庭名称、邀请码和当前角色。
- 家庭页支持通过 `POST /api/v1/families` 创建家庭，并处理空列表、加载中和失败重试。
- `recipe-service` 接入 MySQL/Flyway，新增 `recipe` 和 `recipe_ingredient` 表及 6 道种子菜谱。
- 菜谱服务提供 `GET /api/v1/recipes` 和 `GET /api/v1/recipes/{recipeId}`，无需额外跨服务调用。
- Flutter 菜谱页读取真实菜谱目录，并根据当前冰箱食材计算覆盖率、缺少食材、临期匹配和推荐顺序。
- 菜谱详情展示原料、可选标记和制作步骤。

### S2 家庭协作与多家庭工作区

- 支持 8 位邀请码加入家庭，新成员默认 VIEWER，重复加入幂等。
- 家庭 OWNER 可查看成员、调整 EDITOR/VIEWER、移除成员并转交所有权。
- 所有权转交在事务中同步更新 `family.owner_user_id` 和成员角色，原 OWNER 变为 EDITOR。
- Flutter 按用户持久化当前家庭，切换家庭后冰箱和菜谱重新加载。
- 家庭页提供创建、加入、切换、成员列表和成员操作面板。
